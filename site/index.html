A site only needs three answers about an agent.

Whose agent is it?

The signature standard (Web Bot Auth) tells you which operator signed the request. Ludion adds who they act for.

What is it allowed to do?

A mandate: read, log in, reserve, check out, up to a limit, until an expiry. Requests outside it don't pass.

Who pays if it breaks something?

Ballast. First a public promise with consequences; later real cover. Nobody sells this yet. We will.

For sites: see it before you decide anything.

Install the Gate at pressure 0. It records which agents arrive, which ones prove who they are, and which unverified automation touches checkout, login, and forms. Tomorrow you get a report with real numbers. Nothing is blocked. Humans are never affected.

// Node / Express / Hono / Fastify — Next.js and Workers adapters next
import { ludionGate } from "@ludion/gate-node";
app.use(await ludionGate({ siteId, siteKey, pressure: 0 }));

// Already have logs? See the number without touching the request path:
npx ludion scan access.log

Only request metadata leaves your servers, and only if you say so: route templates, method, classification, decision, a hashed /24. No bodies, no cookies, no query values. Verification runs on your server with cached keys; if Ludion is down, your site isn't.

Pressure is a dial, not a switch.

Blocking on day one is why bot management never gets installed on the long tail: you'd lose real customers arriving through agents. So the Gate starts by watching and lets you raise the pressure one notch at a time. Every rejection carries a link that tells the agent's developer exactly how to become verified. Rejection is recruitment.

0 observe1 favor2 critical routes3 all
0 — observe. Everything passes. You get the daily report: who came, what they touched, how many were unverified.

For agents: a free identity, one line to sign.

Your agent gets blocked because nobody can tell it apart from a scraper. Ludion gives it an identity on the open standard — Web Bot Auth, RFC 9421 — with a directory and a card any verifier can read. Sites running the Gate let verified agents skip the friction. Register once; carry your reputation with you.

npx ludion init            # keys, diver_id, directory + card
npx ludion sign GET https://shop.example/   # headers for curl / httpx / anything

import { ludionFetch } from "@ludion/diver";
const res = await ludionFetch("https://shop.example/api/products?q=camera", {}, { signer });

Identity key and signing key are separate: the identity never signs a request and the signing key rotates. Steal one and you get neither the past nor other sites.
