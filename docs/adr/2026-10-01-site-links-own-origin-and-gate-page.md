# サイトのリンクは自分のオリジンで閉じ、`/gate` はサイトに置く

日付：2026-10-01（夜勤 5、WEB-5）

## 決定

1. WEB-5 の「許可リスト」は、サイト自身のオリジンだけ。第三者のオリジンは1つも載せない（NIGHT.md §2：第三者への通信は無し、フォントも自前）。
   - 読み込み（script、stylesheet、画像、フォント、アイコン、リソースヒント）が他のオリジンを指したら、それだけで失格。
   - 実際の通信は WEB-6 の監視（`site/test/egress.mjs`）で全部見る。クエリは WEB-5 では問わない（ログの漏れは WEB-6 が見る）。
2. リンクは3つに分けて確かめる（`site/test/links.mjs`）。
   - サイトの中（相対、または `https://ludion.ai/...` の絶対 URL）：ビルドした dist で、静的ホストと同じ規則（`serve.mjs` の `resolveFile`）で引けること。フラグメントは着地先の id があること。
   - リポジトリの中（`https://github.com/Ludion-ai/Ludion/...`）：ネットワークに出ず、このチェックアウトにそのパスがあること。`#見出し` は Markdown の見出しから GitHub の slug を作って照合する。main にまだ入っていない新しいページへのリンクでも、PR の中で正しく判定できる。
   - それ以外の外向きのリンク：ネットワークで HEAD（拒まれたら GET）を投げる。404 と 410 だけを「切れている」とする。答えがない（ネットワークなし、タイムアウト、5xx、429）ときは「未確認」と数えて、要約に出す。落とさない。
3. リンクは静的なファイルだけでなく、ブラウザで使ったあとの DOM からも拾う。検索の結果、言語の切り替え先、scan の結果とコピーしたテキストは、スクリプトが作るからだ。
4. `https://ludion.ai/gate` をサイトのページにする（`/gate` と `/ja/gate`）。scan の CLI とコピーのテキスト、日次レポート、Gate の User-Agent がすでにこの URL を配っている。
   - 中身は各アダプタの README（gate-node、gate-next、gate-workers）の「Install」をそのまま移した。書き足した約束はない。
   - scan の画面の「Gate の入れ方」も、GitHub のリポジトリ（ルートに README がない）ではなく `/gate` を指す。

## 捨てた候補

- **外向きのリンクを許可リストで縛る**：新しいリンクを足すたびにリストを広げることになり、それは検証器の緩和になる。ネットワークで確かめるほうが、切れたリンクを実際に捕まえる。
- **外向きのリンクを確かめない**：datatracker の版の名前が変わると、切れたリンクがそのまま残る。
- **リポジトリへのリンクもネットワークで確かめる**：PR の時点では main にないパスが 404 になる。チェックアウトで引けば、決定的で速い。
- **CLI の文面を GitHub の URL に変える**：CLI とレポートはすでに `ludion.ai/gate` を出している。配った URL のほうを生かす。
- **404 ページの日本語の代替リンクを消す**：言語の切り替え（Starlight の picker）も `/ja/404.html` を指すので、消しても切れたリンクが残る。日本語の 404 を置けば両方直り、Cloudflare Pages では `/ja/...` の 404 が日本語で出る。
