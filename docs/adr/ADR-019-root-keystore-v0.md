# ADR-019：v0 の Root 鍵は、パスフレーズで封をしたファイルに置く

日付：2026-09-30

## 決定

Diver の Root 秘密鍵は、`ludion.json` の中に封をした形でだけ保存する。

- 暗号：scrypt（N=2^17、r=8、p=1）でパスフレーズから鍵を導き、AES-256-GCM で 32 バイトの Ed25519 シードを暗号化する。
- AAD：公開鍵（kty・crv・x）と kid。封をした塊を別の身元の下に移せない。
- 開けた後：シードから OpenSSL で公開鍵を導き直し、保存されている公開鍵と一致しなければ拒否する。
- 実装：暗号は `node:crypto`（OpenSSL）だけを使い、CRY-1 の許可リストにある `packages/diver/src/keys.mjs` の中に置く。
- パスフレーズの渡し方：`LUDION_ROOT_PASSPHRASE`。端末なら、エコーなしのプロンプトでもよい。12 文字以上とする。
- 渡されないとき：dev モードでなければ `init` は何も書かずに失敗する。
- 平文の Root：`--dev` または `LUDION_DEV=1` のときだけ許す。その身元を読み込む全コマンドが stderr で警告する。
- dev の印のない平文の Root（古い CLI で作ったもの、手で編集したもの）も警告する。
- 使い道：Root は `sign` にも `rotate` にも使わない。今の CLI で Root を開くのは検査のときだけ。Card の署名と Session 鍵の承認は Registry とともに入れる。

## 理由

- spec §12.4 は Root の置き場所を KMS、HSM、OS のキーチェーンとしている。v0 の CLI はそのどれも持たない。
- シードのままの平文ファイル（シードの状態）は、DIV-3 が禁じる「dev モード以外で平文」そのものだった。
- 封をしたファイルなら、依存を増やさずに今日から平文をなくせる。KMS やキーチェーンのバックエンドは、同じ `sealRootKey` / `openRootKey` の形の後ろに差し込める。

## 捨てた代替案

- **OS のキーチェーン（Windows の DPAPI、macOS の `security`、Linux の `secret-tool`）**：プラットフォームごとに外部コマンドやネイティブ依存が要る。CI やコンテナには存在しない。
- **環境変数に Root そのものを置く**：spec §12.4 が開発時だけに限っている。
- **パスフレーズなしで自動生成した鍵で暗号化し、同じディスクに置く**：平文と変わらない。
- **既定を dev モードにする**：危険な状態が既定になる。

## 見直す条件

- KMS か OS のキーチェーンの対応を入れるとき。既定の置き場所をそちらへ移す。
- scrypt のパラメータが推奨値から外れたとき。
- パスフレーズの入力が DIV-1（3 分）の障害になると分かったとき。
