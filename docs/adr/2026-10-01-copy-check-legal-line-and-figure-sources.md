# 文面の検査：法務の線は「否定がその語に付いているか」で、数字の出所は「リンク先がその数字を言っているか」で測る

日付：2026-10-01（夜勤 6、WEB-2）

## 決定

1. WEB-2 は2つの規則で測る（`site/test/copy.mjs`）。対象はビルドした全ページ（本文、`<title>`、description と og/twitter の description、alt、title、aria-label、placeholder、コード）。scan の画面の文言（`site/src/scan/strings.mjs`）と、コピーされるレポート（CLI の `renderText` を本物のログで回したもの）も、法務の線にかける。
2. **法務の線**（spec §14、§21）。3種類の語を英日で持つ。
   - 保険：insurance、insured、underwrite…／保険
   - 支払いの保証：guarantee、warranty、compensate、reimburse、refund、payout、「we pay」…／保証、補償、賠償、弁済、補填、返金、肩代わり…
   - 絶対の安全：100%、completely safe、risk-free、bulletproof、blocks all…／完全に安全、絶対安全、万全、リスクゼロ、確実に防ぐ、すべてのボットを防ぐ…
   - これらの語は、否定されているときだけ書いてよい（「Ballast v0 is not insurance」「保険ではなく」）。否定はその語に付いていなければならない。
     - 英語：同じ節（`, ; : ( ) — . ! ?` で切る）の中で、語の前の6語以内に否定語（not、no、never、n't…）がある。「not only」「no doubt」は否定ではない。
     - 日本語：語の後の同じ節（`、 。 （ ）` などで切る）で、最初に現れる述語が否定（ない、ません、ではなく…）であって、肯定（ます、です、する…）より前にある。
     - 「100%」は英日で同じ字なので、どちらかの否定が付いていればよい。
   - 語の一覧は広めに取った。技術の意味の guarantee（「署名が保証する」）も引っかかるが、そのときは言い換える。負のオラクルなので、迷ったら落とす側に倒す。
3. **数字の出所**。「数字」を次のように決めた。
   - 数量：単位の付いた数（秒、分、時間、日、%、行、MB、倍、件、つ、requests、agents…）、4桁以上か小数か桁区切りの数、比較の語が付いた数（±、約、最長、about、up to、within…）。英語の数詞（one〜twelve、twenty…）と漢数字（一行、三分）も、単位が付けば数量。「an hour」「a day」も数量。
   - 名前（出所は要らない）：トークンの一部（D0、v0、p99、ed25519、HTTP/1.1、DIV-1、日付）、名付けの語の後（RFC 9421、HTTP 403、Next.js 16、Pressure 0、Depth 0、§14）、年（2026、2026年）、単位のない3桁までの数（「a 200 without redirects」）。
   - 数量は、同じブロック（段落、リストの項目、表のセル）の中のリンクで出所を示す。出所として認めるのは、このリポジトリの文書へのリンクで、リンク先（フラグメントがあればその見出しの節）が同じ値と同じ単位の数量を言っているものだけ。チェックアウトの中で確かめるので、ネットワークは要らない。
   - 行数（「Add two lines」「1行です」）は、そのすぐ後のコードブロックが出所になる。空でない行がちょうどその数でなければならない。
   - 見出しの数字は、その節の中で出所付きで現れればよい（「Get verified in 3 minutes」の 3分は、節の中の DIV-1 へのリンクが支える）。`<title>`、h1、description の数字は、ページのどこかで出所付きで現れればよい。これらはリンクを持てないからだ。
   - scan が計算する数字は、訪問者が落としたログが出所。静的な文面には出ない。CLI と一致することは WEB-4 が見ている。
4. 検査が噛むことを示す。ビルドしたページに、主張と出所のない数字を 21 種類仕込み、すべてを狙いの規則で捕まえる。否定、出所付きの数字、名前を仕込んだ対照 5 種類は、どれも指摘にならない。
5. 最初の実行で捕まえたものを直した。
   - 法務の線：Depth の表の D3 が「an insured Ballast, offered through partners when available」「保険付きの Ballast（パートナー経由で、提供が始まってから）」だった。パートナー経由の保険の提供は、§14 の「保険を売ると言わない」「紹介料を取らない」の線にかかる。→「Ballast v1（Ludion はまだ提供していません）」にした。中身は spec §13.4 と §14 にある。
   - 誇張：トップの「installs in one line」「一行で入る」。測った値（GATE-3）は「アプリ側 3 行以内」で、1行なのは Next.js だけ。→「3 lines of your code or fewer」「コード3行以内」にして、MISSION.md の GATE-3 を出所にした。
   - 「Get verified in 3 minutes」の 3分は、測った値ではなく目標（DIV-1 はまだ PENDING）。→ 検証の道の冒頭に「3分は目標で、DIV-1 として書いてある。クリーンなコンテナで init から VERIFIED まで180秒以内」と書き、MISSION.md の M2 を出所にした。`/gate` の「3分で検証済みになれます」も「目標は3分」に直した。
   - 仕様の数字（署名の寿命60秒、時計のずれ±30秒、Staple の寿命1時間、失効が届くまで1時間、苦情への応答24時間、D4 の90日）には、spec の該当の節へのリンクを付けた。
   - 数字ではない数（「2 つの公開ファイル」「1つの忙しいエージェント」「2回送った」「1本だけ」「どれ一つとして」「not one」）は、数を使わない言い方にした。
6. 速いテスト `site/test/copy.test.mjs` に規則を降ろし、`npm test` に入れた。サイトの Markdown の全行と scan の文言を、ビルドなしで法務の線にかける。D3 の文面そのものも、捕まえるべき主張の一覧に入れた。

## 捨てた候補

- **禁止語の単純な一覧**：「Ballast v0 は保険ではありません」まで落ちる。§14 の線を守る文面こそ保険に触れるので、否定を読めないと、正しい断りを書けなくなる。
- **ページ全体に否定語があれば通す**：「No signup: buy insurance」「保険を提供し、署名がない…」がすり抜ける。否定は語に付いていなければ意味がない。対照として検査に入れた。
- **数字のそばにリンクがあれば通す**（STATE.md の入口に書いた案）：リンク先が何でもよいなら、出所の偽装が通る。リンク先がその数字を言っていることまで見る。サイトの中のページへのリンクは出所にしない。循環（A が B を、B が A を出所にする）を断つためだ。
- **外部の文書（datatracker など）を出所に認める**：オフラインでは中身を確かめられない。今の数字はすべて spec と MISSION.md で支えられる。要るようになったら、WEB-5 と同じくネットワークで取りに行く形で足す。
- **形態素解析器を入れる**：依存が重く、サイトのテストのために入れる理由が薄い。節と最初の述語の近似で、仕込んだ罠（離れた否定、先行する否定、「not only」）は全部見分けられた。

## 未決

- 数量の単位の一覧は有限。一覧にない名詞を数える数（例：「3 regions」）は、4桁未満で比較の語がなければ数量と見なさない。新しい数字を書くときは単位の一覧も見る。
- 法務の線の語の一覧も有限。言い換え（「万一のときは全額お支払い」など）は、語に当たらなければすり抜ける。仕込みの一覧を増やして育てる。
- 日次レポートのメール（`ludion report`）の文面は、サイトではないので WEB-2 の外。RPT-1 の対に同じ規則をかけるかは、次に決める。
- 出所の MISSION.md と spec は日本語。英語のページから日本語の文書へリンクしている。英語の spec ができたら差し替える。
