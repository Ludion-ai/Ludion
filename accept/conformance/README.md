# Gate conformance vectors

`vectors.json` is the conformance suite every Ludion Gate runs, whatever its language (oracle GATE-9). It holds:

- the WG test vector (`draft-ietf-webbotauth-httpsig-protocol-00` Appendix E.2.1);
- STD-2's negative cases (`packages/gate-core/test/std2.test.mjs`): one case per STD-2 test, where each step changes one thing from a VERIFIED request;
- every attack in the GATE-7 corpus (`accept/attacks/`), with its controls, written out as concrete requests.

It is generated by `export.mjs` from the corpus and the attack families (`accept/attacks/families.mjs`). Oracle GATE-10 checks that the file equals a fresh export byte for byte, matches the corpus one for one, carries no private key, and that the TypeScript Gate passes every case reading nothing but the file. The TypeScript Gate runs it on Node here and on Deno and workerd through NEUT-1. Keys and nonces are seeded from each case id, so adding an attack adds only its case. The seeded keys are throwaway test keys; only public keys are in the file.

```sh
node accept/conformance/export.mjs     # after adding to accept/attacks/
```

## Format

```jsonc
{
  "version": 1,
  "defaults": { "now": 1800000000000, "siteId": "site-test", "pressure": 0,
                "routes": [{ "match": "/checkout/**", "pressure": 2 }, { "match": "/login", "pressure": 2, "require": { "depth": 1 } }],
                "site": "https://shop.example" },
  "cases": [{
    "id": "replay--get", "source": "GATE-7", "family": "replay", "title": "…", "params": { … },
    "now": 1735689601000,                        // optional; else defaults.now (milliseconds)
    "world": {
      "registry": { "issuer": "https://registry.ludion.ai", "keys": [ /* Ed25519 public JWKs */ ] },
      "documents": [{ "url": "https://attacker.example/card", "contentType": "application/json", "body": { … } }]
    },
    "gates": {
      "main": { "adapter": "core", "authorities": ["shop.example"], "nonceCache": { "maxEntries": 40 },
                "directories": [{ "uri": "https://agent.example", "keys": [ /* public JWKs */ ] }] },
      "g1":   { "adapter": "node", "authorities": ["shop.example"], "trustProxy": true, "directories": [ … ] }
    },
    "steps": [
      { "gate": "main", "atS": 0, "expect": "verified",
        "core": { "method": "GET", "targetUri": "https://shop.example/checkout/1", "fields": [{ "name": "…", "value": "…" }] },
        "reference": { "class": "VERIFIED", "action": "allow" } },
      { "gate": "g1", "atS": 1, "expect": "rejected",
        "raw": { "method": "GET", "target": "/CHECKOUT/1", "rawHeaders": ["host", "shop.example", …], "tls": true, "remoteAddress": "203.0.113.7" },
        "reference": { "class": "SUSPECTED", "action": "deny", "error": "signature_required", "reachedApp": false } },
      { "atS": 0, "expect": "valid",
        "signature": { "request": { … }, "directories": [ … ] }, "reference": { "keyid": "…", "identifier": "…" } }
    ]
  }]
}
```

### Setting up a case

- **Gates.** Build one Gate per entry in `gates`, with:
  - the site's `routes` at `pressure` 0;
  - its `authorities` (`null` means none are configured: the Gate is unpinned);
  - the Registry's keys and issuer (for Staples);
  - a nonce cache of `nonceCache.maxEntries` if given.
- **Key discovery.** Seed each Gate's key discovery with `directories`: the key directory at `<uri>/.well-known/http-message-signatures-directory` returns `{ "keys": [...] }`. Serve `world.documents` at their URLs (for example CIMD cards). Nothing else is reachable.
- **Time.** The clock is `now + atS × 1000` ms at each step, in order. State such as the nonce cache and the directory cache carries over from step to step.

### Running a step

- **`core`**: a request as the Gate's core sees it, the RFC 9421 message: method, target URI, and header fields in order.
- **`raw`**: a request as the web server receives it. Your adapter turns it into the core request the way it does in production:
  - the authority comes from `Host`, or from `X-Forwarded-Host` / `X-Forwarded-Proto` when `trustProxy` is set;
  - an absolute-form target is routed on its path;
  - a denial answers the request itself, and anything else reaches the app.
- **`signature`**: the RFC 9421 / Web Bot Auth signature on its own, with the lifetime left to the caller. A Gate adds its own cap: `expires - created` of at most an hour, and a nonce once it passes 60 seconds (spec §10.4). `wg-e2-1--gate-holds-to-60s` checks the cap. Its id predates the hour limit.

### What each step must satisfy

| `expect` | The step must |
|---|---|
| `verified` | be classified VERIFIED (a control: the setup is honest); with `identifier`, attributed to that key directory |
| `rejected` | not be VERIFIED, carry no Staple standing, be denied if the route is at Pressure ≥ 2, and, for `raw`, never reach the app and carry `Ludion-Error` |
| `human` | (`raw`) reach the app untouched: no `Ludion-Error` |
| `denied` | (`raw`) be answered 401 or 403 before the app (a control: the route is protected) |
| `flood` | nothing; it is the attacker's own traffic |
| `valid` / `invalid` | (`signature`) verify / not verify; a valid one with the reference `keyid` and directory `identifier` |

`classes`, where given (STD-2), is normative: spec §10.8 says a keyid missing from the directory is UNVERIFIED and a failed verification is SPOOFED. `note` says what the step changes.

`reference` is what the TypeScript Gate answered. Another Gate must meet `expect`. Matching `reference.class` is a good sign, but it is not required.
